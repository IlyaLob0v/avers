# Выгрузка структуры схемы JACK — инструкция для администратора Oracle

Проект «Аверс» переводит учёт со старой базы Oracle (схема `JACK`) на PostgreSQL. Чтобы спроектировать перенос,
нам нужна **структура** схемы: таблицы, столбцы, ключи, объёмы, код процедур. **Данные абонентов не нужны** —
скрипты ниже их не читают.

Что важно знать:

- Все скрипты **только читают** словарь базы. Ничего не создают, не меняют и не удаляют.
- Запускать под пользователем с правами на словарь (`SYSTEM` или любой с `SELECT_CATALOG_ROLE`).
- Скрипты рассчитаны на Oracle 10.2 и SQL*Plus из клиента 10, работают и на новых версиях (проверены на Oracle 23 Free).
- Нагрузка на базу — как от нескольких запросов к словарю. Исключение — шаг 3 (необязательный).

## Запуск (Linux)

Нужен компьютер с Linux, на котором установлен клиент Oracle (`sqlplus` и `expdp`): удобнее всего сам сервер базы.
Под пользователем `oracle` (или другим, у кого настроено окружение Oracle):

```bash
. oraenv                      # если sqlplus не находится: задаёт ORACLE_HOME и PATH
unzip для-администратора-oracle.zip && cd jack-structure
./jack-export.sh system@avers102
```

Запускать именно `./jack-export.sh`. Файлы `*.sql` — не программы для терминала: их выполняет SQL*Plus,
и скрипт сам передаёт их ему.

Можно запустить и с другого компьютера с Linux, где стоит только Oracle Instant Client (`sqlplus`).
Тогда базу указывают адресом сервера: `./jack-export.sh system@//servora:1521/<имя службы>`.
Если `expdp` на этом компьютере нет, скрипт выполнит шаг 1 и пропустит шаг 2.

Скрипт спросит пароль `SYSTEM`, а на шаге Data Pump `expdp` спросит его ещё раз. Если схема называется не `JACK`,
поправьте строку `define owner = JACK` в `00-run-all.sql` и `SCHEMAS=JACK` в `expdp-metadata.par`.
Кодировку (`NLS_LANG`, UTF-8) скрипт задаёт сам, чтобы русские комментарии к таблицам не исказились.

Скрипт делает два шага.

**Шаг 1. Структура и код** (`00-run-all.sql`). В папке появятся файлы:

| Файл | Что внутри |
|---|---|
| `jack_01_*.csv` | версия Oracle и кодировка базы |
| `jack_02_*.csv` | список объектов схемы |
| `jack_03_*.csv` | объём схемы и таблиц (нужно, чтобы понять, хватит ли бесплатного Oracle Free с лимитом 12 ГБ) |
| `jack_04_*.csv` | столбцы и комментарии к ним |
| `jack_05..09_*.csv` | ключи, индексы, последовательности, зависимости, синонимы, ссылки на другие базы (без паролей), права |
| `jack_10..13_*` | исходный код процедур, пакетов, триггеров, представлений, задания по расписанию |
| `jack_20_ddl.sql` | DDL всей схемы |

**Шаг 2. Data Pump** (`expdp-metadata.par`). Тот же DDL, но в формате, который мы восстановим на тестовом стенде
без данных. Файлы `jack_metadata.dmp` и `jack_metadata.log` Oracle пишет в каталог `DATA_PUMP_DIR` на сервере базы;
скрипт копирует их в папку со скриптами. Если скрипт запущен не на сервере базы, он напишет, из какого каталога
забрать эти два файла.

В конце скрипт собирает всё в один архив `jack-structure-<дата>.tar.gz`.

## Точное число строк (по желанию, вне рабочего времени)

```bash
./jack-export.sh --row-counts system@avers102
```

Скрипт считает строки в каждой таблице — для этого он **просматривает таблицы целиком**, поэтому запускать его
лучше вечером. В файл `jack_30_row_counts.csv` попадают только числа.

## Что передать

Архив `jack-structure-<дата>.tar.gz` (и `jack_30_row_counts.csv`, если считали строки) — разработчикам на флешке
или через внутреннюю сеть, не по почте и не в git: репозиторий проекта публичный. Если какой-то шаг выдал
ошибку — ничего страшного, пришлите файлы как есть вместе с текстом ошибки.
