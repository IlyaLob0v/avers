# db/stand — стенд переноса Oracle JACK → PostgreSQL

Стенд повторяет на отдельном компьютере путь из `docs/04-db-migration-plan.md`:

```text
выгрузка JACK (expdp) → Oracle Free 23 → Ora2Pg 25 → PostgreSQL 18, схема legacy → сверка
```

Боевые базы стенд не трогает: он работает только с контейнерами из `db/docker-compose.yml`.
На стенде будут персональные данные, поэтому он должен стоять **внутри сети предприятия**, а порты баз
открыты только на самом компьютере (127.0.0.1).

## Что нужно

- Docker Desktop (Windows) или Docker (Linux), около 20 ГБ на диске плюс размер выгрузки.
- Git Bash (ставится вместе с Git для Windows). Команды ниже — из корня репозитория.
- Файл `.env` в корне репозитория (образец — `.env.example`): пароли стендовых баз `PG_PASSWORD`, `ORA_PASSWORD`.

## Порядок работы

1. **Проверить стенд без настоящих данных** — репетиция на выдуманной схеме `AVERS_DEMO`:

   ```bash
   bash db/stand/stand.sh selftest
   ```

   Создаёт учебную схему в Oracle, выгружает её `expdp`, восстанавливает, переносит в PostgreSQL
   (`legacy_selftest`), сверяет, а затем портит одну сумму на копейку и проверяет, что сверка это заметила.
   В конце должно быть «САМОПРОВЕРКА ПРОЙДЕНА».

2. **Положить выгрузку** `jack.dmp` (от администратора Oracle) в `db/legacy/dumps/` — эта папка не попадает в git.

3. **Запустить перенос целиком:**

   ```bash
   bash db/stand/stand.sh all jack.dmp
   ```

   или по шагам: `import jack.dmp` → `report` → `schema` → `data` → `reconcile`. Каждый шаг можно повторять:
   схема Oracle на стенде и схема `legacy` в PostgreSQL пересоздаются заново.
   Если выгрузка сделана старой утилитой `exp`, а не `expdp`, вместо `import` — `import-exp jack.dmp`.

Подойдёт и выгрузка только структуры (`jack_metadata.dmp`, см. `db/legacy/README.md`): тогда `schema` покажет,
как Ora2Pg переводит таблицы, ещё до прихода данных.

## Что получится

Всё — в `db/legacy/dumps/stand/legacy/` (не в git):

| Файл | Что это |
|---|---|
| `ora2pg-report.html` | отчёт Ora2Pg: объекты схемы и оценка сложности переноса |
| `schema/table.sql`, `sequence.sql`, `*_table.sql` | таблицы, последовательности, ключи и индексы для PostgreSQL |
| `code/*.sql` | черновой перевод представлений, процедур, пакетов, триггеров — **только для разбора**, в базу не грузится |
| `oracle_fingerprint.csv` | отпечаток Oracle: агрегаты по таблицам (без персональных данных) |
| `reconcile-*.txt` | отчёт сверки |

В PostgreSQL: схема `legacy` — копия JACK «как есть», схема `recon` — служебные таблицы сверки.

## Как устроена сверка

С обеих сторон снимается «отпечаток» каждой таблицы — только агрегаты, содержимое строк не сравнивается и не выводится:
число строк; по каждому столбцу — число непустых значений; для чисел — точная сумма; для дат — минимум и максимум;
для строк — суммарная длина. Отпечаток Oracle — `oracle/fingerprint.sql`, PostgreSQL — `db/migration/reconcile/`.

| Проверка | Если не прошла |
|---|---|
| Отпечатки совпадают | перенос не принят, `reconcile` завершается с ошибкой |
| Кириллица: нет «??», «кракозябр» (`РџСЂРё…`, `ÐŸÑ€Ð¸…`) и символа «�» | предупреждение со счётчиками по столбцам |
| Сверка с бухгалтерией (август 2026) | пока «запрос не задан»: запросы впишем после разбора DDL JACK |

## Настройки

- `ora2pg/ora2pg.conf` — паролей нет. Главное: деньги остаются `numeric` (`PG_NUMERIC_TYPE 0`, `DEFAULT_NUMERIC numeric`),
  имена в нижнем регистре, ключи и индексы создаются после загрузки данных.
- `ORA_SCHEMA` (по умолчанию `JACK`) и `PG_SCHEMA` (по умолчанию `legacy`) можно задать перед командой:
  `ORA_SCHEMA=JACK PG_SCHEMA=legacy_try2 bash db/stand/stand.sh all jack.dmp`. Схема PostgreSQL обязана начинаться с `legacy` —
  стенд пересоздаёт её и не должен задеть новую модель.
- Ограничение Oracle Free — 12 ГБ данных. Если JACK больше (видно по `jack_03_schema_size.csv`), план Б —
  временная установка Oracle на сервере предприятия или Ora2Pg прямо с боевой базы (только чтение, Instant Client 11.2/12.1).
  В этом случае в `ora2pg.conf` меняется `ORACLE_DSN` и `NLS_LANG` (`AMERICAN_AMERICA.CL8MSWIN1251`).
