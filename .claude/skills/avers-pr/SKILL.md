# Ветка, коммит, PR

1. Ветка от свежего `main`: `feature/<кратко>`, `fix/<кратко>` или `docs/<кратко>`. В `main` не коммить.
2. Перед коммитом с кодом — скилл `avers-verify`. Перед крупным PR — `engineering:code-review`
   и `security-review`.
3. Проверь, что в индексе нет: `.env`, паролей, строк подключения к боевым базам, выгрузок
   `db/legacy/dumps/`, персональных данных абонентов (ФИО, телефоны, адреса).
   `git diff --cached --stat` и беглый просмотр diff обязательны.
4. Коммит по-русски: `<область>: <что сделано>`. Области: `оболочка`, `сервер`, `домен`, `миграция`, `1с`,
   `отчёты`, `документация`, `инфраструктура`. Один коммит — одна мысль.
5. `git push` и создание PR — с подтверждения пользователя (облачная сессия проекта Claude работает по своим
   правилам и открывает PR сама). Force-push запрещён.
6. Описание PR по-русски, для нетехнического читателя:
   - «Было:» — что видел пользователь до изменения; «Стало:» — что видит теперь;
   - «Как:» — коротко о решении, ссылки на ADR и требования `REQ-…`/`Q-NN`;
   - «Проверка:» — итоговые строки сборки, тестов и format.
7. Дождись зелёного CI. Красный — чинить в этой же ветке, не отключая тесты и проверки.
8. Merge в `main` — только когда пользователь скажет.
