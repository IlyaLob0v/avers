# Проверка запросов на большом наборе

Программа создаёт отдельную базу с искусственными счетами, месячными начислениями и исходными операциями.
После прогона база удаляется. Существующие базы не изменяются. Запускайте на изолированном PostgreSQL стенде:
построение набора и параллельные запросы создают существенную нагрузку.

Подключение задаётся переменной `AVERS_TEST_POSTGRES`, как у серверных тестов. Пароль не передавайте аргументом команды.

```sh
dotnet run --project tools/Avers.DataProbe -c Release -- 10000 348 16
```

Аргументы: число счетов, число месяцев с января 1998 года, число параллельных запросов должников.
Пример создаёт 3,48 млн месячных строк и 2,32 млн исходных операций. В одном доме — 1000 счетов.
Быстрая самопроверка: `25 12 2`.

Сначала проверяются число строк, границы страницы и денежный итог по искусственному эталону.
Потом измеряются пять прогретых повторов с сериализацией JSON и параллельные запросы должников.
JSON в стандартном выводе содержит размер базы, ответов и измерения; сообщения о ходе идут в stderr.

Это измерение запросов на компьютере стенда. Оно не подтверждает время HTTP, отзывчивость интерфейса,
работу восьми xrdp-сеансов, совместную нагрузку 1С или правильность миграции настоящих данных JACK.
