# 09. Сервер Аверса и общая база

Чтобы все сотрудники работали в одной базе, в офисе нужен один всегда включённый компьютер с Linux.
На нём работают сервер Аверса и база PostgreSQL, а программы сотрудников подключаются к нему по локальной сети.
Это может быть тот же сервер, что и для Windows 7 ([08](08-terminal-server.md)). Интернет не нужен.

## 1. Что нужно

| Что | Какое |
|---|---|
| Сервер | **Ubuntu Server 24.04 LTS**, можно тот же, что для xrdp |
| Память | +1 ГБ к тому, что уже нужно серверу |
| Диск | +10 ГБ под базу и ночные копии |
| Сеть | Порт **5115** доступен с компьютеров сотрудников |

### Если в офисе есть только сервер с Windows Server

Linux можно поставить в виртуальную машину Hyper-V на этом сервере (в Windows Server 2019 Datacenter
она не требует лицензий; процессор должен поддерживать виртуализацию, она включается в BIOS).
Включение роли Hyper-V и создание внешнего коммутатора требуют перезагрузки и на минуту прерывают сеть,
поэтому делайте это в нерабочее время, особенно если на сервере работает 1С.

1. **Диспетчер серверов** → «Добавить роли и компоненты» → роль **Hyper-V** → перезагрузка.
2. **Диспетчер Hyper-V** → «Диспетчер виртуальных коммутаторов» → **Внешний**, привязать к сетевой карте сервера,
   галочку «Разрешить управляющей ОС использовать этот сетевой адаптер» оставить.
3. «Создать» → «Виртуальная машина»: **поколение 2**; память **8192 МБ**, динамическую память выключить;
   сеть — внешний коммутатор из шага 2; новый диск **40 ГБ** на томе, где есть место;
   установка из образа `ubuntu-24.04-live-server-amd64.iso`.
4. До первого запуска, в параметрах машины: «Безопасность» → шаблон **Microsoft UEFI Certificate Authority**
   (иначе Ubuntu не загрузится); «Процессор» → **4**; «Автоматическое действие при запуске» → **Всегда запускать**;
   «Автоматическое действие при завершении» → **Завершить работу гостевой ОС**.
5. Запустите машину и установите Ubuntu: при установке задайте постоянный IP-адрес и поставьте галочку **OpenSSH server**.

Дальше всё как на обычном сервере: этот раздел и [08](08-terminal-server.md). 8 ГБ хватает на 8 сотрудников через xrdp
и сервер Аверса с запасом.

## 2. Установка

1. Скачайте сборку: GitHub → **Actions** → последний зелёный запуск **CI** → внизу **Artifacts** →
   **Avers-server-linux-x64**. Перенесите архив на сервер и распакуйте (`unzip Avers-server-linux-x64.zip -d avers-server`).
2. В распакованной папке выполните:
   ```
   sudo bash install.sh
   ```
   Скрипт ставит PostgreSQL, создаёт базу `avers` со случайным паролем, кладёт сервер в `/opt/avers-server`
   и запускает его как службу `avers-server`: она поднимается сама после перезагрузки.
   В конце скрипт пишет адрес, например `http://192.168.1.10:5115`.
3. Смените пароль администратора. В новой базе заведены учебные пользователи (`admin`, `orlov`, `orlova`, `sokolova`,
   `engineer`, `lawyer`, `novikov`) с паролем `avers` и учебные абоненты.
   ```
   sudo avers-password admin
   ```
   Пароль — не короче 6 символов. Дальше сотрудников заводят в программе: войдите как `admin`,
   откройте «Права доступа», заведите каждого со своим паролем и ролью. Учебных пользователей отключите
   галочкой «Отключён», чтобы под ними никто не вошёл.

Обновление: распакуйте новую сборку и снова выполните `sudo bash install.sh`. База и пароли сохраняются,
таблицы сервер обновит сам при запуске.

## 3. Подключить программы

Создайте файл `avers.json` с адресом из шага 2:

```
{ "server": "http://192.168.1.10:5115" }
```

- **Сервер xrdp (Windows 7):** файл `/opt/avers/avers.json`.
- **Компьютер с Windows 10:** рядом с `Avers.exe`.

На экране входа внизу должно быть написано «сервер 192.168.1.10:5115». Сотрудник вводит свой логин и пароль.

### Телефон радиомеханика

В браузере телефона откройте `http://192.168.1.10:5115/m/` и войдите логином и паролем механика (роль «Читатель»).
Механик ищет дом по улице и номеру и видит управляющую компанию, технику дома, неустранённую неисправность
и список схем СКПТ. Править ничего нельзя.

**С выезда, через интернет.** Из интернета видна только эта страница, по защищённому соединению (HTTPS);
абоненты, оплаты и настольная программа остаются доступны только в офисе.

1. Купите или возьмите у владельца сайта имя для сервера, например `avers.avers-servis.ru`,
   и попросите направить его на внешний IP-адрес офиса (запись типа A). Внешний адрес должен быть постоянным.
   Если DNS домена ведётся в панели хостинга (например, jino.ru): в настройках DNS домена добавьте запись
   типа **A**, имя `avers`, значение — внешний IP офиса. Имя начинает работать в течение нескольких часов;
   проверить: `nslookup avers.avers-servis.ru` должен вернуть внешний IP.
2. На роутере офиса пробросьте порты 80 и 443 на этот сервер. Порт 5115 наружу не открывайте.
   Для MikroTik (RouterOS 7): Winbox → **New Terminal**, вместо `192.168.1.10` — адрес сервера:
   ```
   /ip firewall nat add chain=dstnat in-interface-list=WAN protocol=tcp dst-port=80,443 action=dst-nat to-addresses=192.168.1.10 comment="Avers: механики"
   ```
   Список интерфейсов `WAN` есть в заводской настройке MikroTik. Если его нет, вместо `in-interface-list=WAN`
   укажите порт, в который приходит интернет, например `in-interface=ether1`.
3. Смените всем пользователям учебный пароль `avers` (или отключите лишних в «Правах доступа»):
   без этого команда ниже откажется работать.
4. Выполните `sudo avers-internet avers.avers-servis.ru` (своё имя).
   Через пару минут на телефоне откроется `https://avers.avers-servis.ru/m/`.

## 4. Копии базы

Каждую ночь база копируется в `/var/backups/avers` (файл на каждый день, хранятся 30 дней).
Если сломается сам сервер, копия на нём не поможет, поэтому копии каждый день переносятся на другой компьютер
с Linux (ниже `admin@192.168.1.11` — пользователь и адрес этого компьютера). На нём должен работать вход по SSH
(`sudo apt install openssh-server`). На сервере Аверса один раз выполните:

```
sudo ssh-keygen -t ed25519 -N "" -f /root/.ssh/id_ed25519
sudo ssh-copy-id -i /root/.ssh/id_ed25519.pub admin@192.168.1.11
sudo crontab -e
```

и добавьте в конец строку (каждый день в 12:00; если компьютер был выключен, пропущенные копии уйдут на следующий день):

```
0 12 * * * rsync -a /var/backups/avers/ admin@192.168.1.11:avers-backups/
```

Проверка: на другом компьютере в папке `~/avers-backups` есть копия за сегодня. Старые копии там сами не удаляются;
раз в несколько месяцев удаляйте лишние.

Восстановить из копии (все сотрудники должны выйти из Аверса):

```
sudo systemctl stop avers-server
sudo -u postgres pg_restore --clean --if-exists -d avers /var/backups/avers/avers-2026-10-19.dump
sudo systemctl start avers-server
```

## 5. Если что-то не так

| Признак | Что сделать |
|---|---|
| «Нет связи с сервером» в программе | Проверьте `sudo systemctl status avers-server` и что порт 5115 не закрыт сетевым экраном |
| Служба не запускается | `sudo journalctl -u avers-server -n 50` — последние сообщения сервера |
| Сотрудник забыл пароль | Администратор задаёт новый в «Правах доступа»; если забыл сам администратор — `sudo avers-password admin` |
| На входе написано «учебная база на этом компьютере» | Нет файла `avers.json` или в нём ошибка |

## Чего пока нет

- Данные учебные. Настоящие данные из старой базы (JACK) перенесём отдельным шагом ([04](04-db-migration-plan.md)).
- Связь программы с сервером не шифруется. Внутри локальной сети предприятия это допустимо; выпускать порт 5115 в интернет нельзя
  (в интернет открывается только страница механиков через `avers-internet`).
- Отключение и смена роли действуют сразу: отключённому сотруднику программа на первом же действии предлагает войти заново. Кнопки по новой роли появятся после следующего входа.
