# 09. Сервер Аверса и общая база

Чтобы все сотрудники работали в одной базе, в офисе нужен один всегда включённый компьютер с Linux.
На нём работают сервер Аверса и база PostgreSQL, а программы сотрудников подключаются к нему по локальной сети.
Это может быть тот же сервер, что и для Windows 7 ([08](08-terminal-server.md)). Интернет не нужен.

## 1. Что нужно

| Что | Какое |
|---|---|
| Сервер | **Ubuntu Server 24.04 LTS**, можно тот же, что для xrdp |
| Память | +1 ГБ к тому, что уже нужно серверу |
| Диск | под базу и 30 ночных копий; сколько — в разделе 4 («Сколько места нужно копиям») |
| Сеть | Постоянный IP-адрес; порт **443** (HTTPS) доступен с компьютеров сотрудников |

### Если в офисе есть только сервер с Windows Server

Linux можно поставить в виртуальную машину Hyper-V на этом сервере (в Windows Server 2019 Datacenter
она не требует лицензий; процессор должен поддерживать виртуализацию, она включается в BIOS).
Включение роли Hyper-V и создание внешнего коммутатора требуют перезагрузки и на минуту прерывают сеть,
поэтому делайте это в нерабочее время, особенно если на сервере работает 1С.

1. **Диспетчер серверов** → «Добавить роли и компоненты» → роль **Hyper-V** → перезагрузка.
2. **Диспетчер Hyper-V** → «Диспетчер виртуальных коммутаторов» → **Внешний**, привязать к сетевой карте сервера,
   галочку «Разрешить управляющей ОС использовать этот сетевой адаптер» оставить.
3. «Создать» → «Виртуальная машина»: **поколение 2**; память **8192 МБ**, динамическую память выключить;
   сеть — внешний коммутатор из шага 2; новый диск **40 ГБ** на томе, где есть место;
   установка из образа `ubuntu-24.04-live-server-amd64.iso`.
4. До первого запуска, в параметрах машины: «Безопасность» → шаблон **Microsoft UEFI Certificate Authority**
   (иначе Ubuntu не загрузится); «Процессор» → **4**; «Автоматическое действие при запуске» → **Всегда запускать**;
   «Автоматическое действие при завершении» → **Завершить работу гостевой ОС**.
5. Запустите машину и установите Ubuntu: при установке задайте постоянный IP-адрес и поставьте галочку **OpenSSH server**.

Дальше всё как на обычном сервере: этот раздел и [08](08-terminal-server.md). 8 ГБ хватает на 8 сотрудников через xrdp
и сервер Аверса с запасом.

## 2. Установка

1. Скачайте сборку: GitHub → **Actions** → последний зелёный запуск **CI** → внизу **Artifacts** →
   **Avers-server-linux-x64**. Перенесите архив на сервер и распакуйте (`unzip Avers-server-linux-x64.zip -d avers-server`).
2. В распакованной папке выполните:
   ```
   sudo bash install.sh
   ```
   Скрипт ставит PostgreSQL и Caddy, создаёт базу `avers` со случайным паролем, кладёт сервер в `/opt/avers-server`
   и запускает его как службу `avers-server`: она поднимается сама после перезагрузки. Сам сервер слушает только
   этот компьютер, сотрудники подключаются к нему через Caddy по защищённому соединению (HTTPS, порт 443).
   Если на сервере включён сетевой экран `ufw`, скрипт сам открывает порт 443.
3. В конце скрипт пишет адрес для программ, путь к корневому сертификату и его контрольную сумму, например:
   ```
   Сервер Аверса работает. Адрес для программ (avers.json): https://192.168.1.10
   Корневой сертификат для рабочих мест: /usr/local/share/ca-certificates/avers-root.crt
     контрольная сумма SHA256: 3f2a…
   ```
   Перепишите контрольную сумму: она понадобится в разделе 3.
4. При первой установке база пустая, и скрипт просит придумать пароль администратора (логин `admin`,
   не короче 6 символов). Если пропустили, задайте его командой `sudo avers-password admin`.
   Дальше сотрудников заводят в программе: войдите как `admin`, откройте «Права доступа»,
   заведите каждого со своим паролем и ролью.

В адрес и сертификат попадают первый IP-адрес сервера и его имя. Если сотрудники открывают сервер по другому
адресу или имени, перечислите все при установке:
`sudo AVERS_ADDRESSES="192.168.1.10 avers-srv" bash install.sh`. Список запоминается, при обновлении его повторять
не нужно.

Обновление: распакуйте новую сборку и снова выполните `sudo bash install.sh`. Перед обновлением скрипт делает
копию базы (`/var/backups/avers/pre-update-<дата-время>.dump`); если копия не получилась, обновление
отменяется и продолжает работать прежняя версия. База и пароли сохраняются, таблицы сервер обновит сам при запуске.

На серверах, установленных до 29.10.2026, в базе есть учебные пользователи (`orlov`, `orlova`, `sokolova`,
`engineer`, `lawyer`, `novikov`) с паролем `avers`: смените им пароли или отключите галочкой «Отключён».
Проверить, у кого остался учебный пароль: `sudo avers-demo-check`.

## 3. Подключить программы

### Корневой сертификат на рабочие места

Сертификат HTTPS в офисе выпускает сам сервер (свой центр сертификации Caddy). Чтобы программы ему доверяли,
корневой сертификат сервера один раз ставится на каждый компьютер.

**Компьютер с Windows 10 или 11:**

1. Скачайте файл с сервера. В командной строке Windows (вместо `admin` — ваш пользователь на сервере):
   ```
   scp admin@192.168.1.10:/usr/local/share/ca-certificates/avers-root.crt .
   ```
   Или перенесите файл `avers-root.crt` на флешке.
2. Положите рядом с ним `install-root-cert.cmd` из папки сборки сервера.
3. Правой кнопкой по `install-root-cert.cmd` → **«Запуск от имени администратора»**. Сверьте контрольную сумму
   с той, что написал `install.sh`, и нажмите `1`. Должно появиться «Готово».

**Сервер xrdp (Windows 7 и 8):** если сервер Аверса стоит на этом же компьютере, сертификат уже установлен.
Если на другом — положите `avers-root.crt` рядом с `install.sh` из сборки `Avers-linux-x64` и выполните его
ещё раз ([08](08-terminal-server.md)).

### Адрес сервера

Создайте файл `avers.json` с адресом из раздела 2:

```
{ "server": "https://192.168.1.10" }
```

- **Сервер xrdp (Windows 7 и 8):** файл `/opt/avers/avers.json`.
- **Компьютер с Windows 10 или 11:** рядом с `Avers.exe`.

На экране входа внизу должно быть написано «сервер 192.168.1.10». Сотрудник вводит свой логин и пароль.
Без файла программа не открывается и пишет «Не задан адрес сервера Аверса». Учебная база на компьютере
запускается только ключом `--demo` (для обучения, см. [getting-started.md](getting-started.md)).

### Переход с http на https

Серверы, установленные до 09.11.2026, принимали программы по `http://…:5115`. После обновления этот порт закрыт,
и `install.sh` напоминает об этом в конце. На каждом рабочем месте:

1. Поставьте корневой сертификат (выше).
2. В `avers.json` замените `http://192.168.1.10:5115` на `https://192.168.1.10`.

Пока это не сделано, программа на этом месте пишет «Нет связи с сервером».

### Телефон радиомеханика

Страница механика — `/m/` на том же сервере. Механик входит своим логином и паролем (роль «Читатель»),
ищет дом по улице и номеру и видит управляющую компанию, технику дома, неустранённую неисправность
и список схем СКПТ. Править ничего нельзя.

**В офисе, по Wi-Fi:** `https://192.168.1.10/m/`. Телефон не знает корневой сертификат сервера и предупредит
о небезопасном соединении. Поставьте сертификат и на телефон: перенесите на него `avers-root.crt`, затем
на Android «Настройки → Безопасность → Шифрование и учётные данные → Установить сертификат → Сертификат ЦС».
Или пользуйтесь интернет-адресом ниже, у него обычный сертификат.

**С выезда, через интернет.** Из интернета видна только эта страница, по защищённому соединению (HTTPS);
абоненты, оплаты и настольная программа остаются доступны только в офисе. Войти из интернета могут только
сотрудники с ролью «Читатель»; неверные пароли оттуда не закрывают сотруднику вход в офисе.

1. Купите или возьмите у владельца сайта имя для сервера, например `avers.avers-servis.ru`,
   и попросите направить его на внешний IP-адрес офиса (запись типа A). Внешний адрес должен быть постоянным.
   Если DNS домена ведётся в панели хостинга (например, jino.ru): в настройках DNS домена добавьте запись
   типа **A**, имя `avers`, значение — внешний IP офиса. Имя начинает работать в течение нескольких часов;
   проверить: `nslookup avers.avers-servis.ru` должен вернуть внешний IP.
2. На роутере офиса пробросьте порты 80 и 443 на этот сервер. Офисный сайт из интернета не открывается:
   сервер отвечает на него только адресам локальной сети.
   Для MikroTik (RouterOS 7): Winbox → **New Terminal**, вместо `192.168.1.10` — адрес сервера:
   ```
   /ip firewall nat add chain=dstnat in-interface-list=WAN protocol=tcp dst-port=80,443 action=dst-nat to-addresses=192.168.1.10 comment="Avers: механики"
   ```
   Список интерфейсов `WAN` есть в заводской настройке MikroTik. Если его нет, вместо `in-interface-list=WAN`
   укажите порт, в который приходит интернет, например `in-interface=ether1`.
3. Если сервер ставился до 29.10.2026, смените учебным пользователям пароль `avers` (или отключите их
   в «Правах доступа»): без этого команда ниже откажется работать.
4. Выполните `sudo avers-internet avers.avers-servis.ru` (своё имя).
   Через пару минут на телефоне откроется `https://avers.avers-servis.ru/m/`.

### Офлайн-карта

Карта Омска (OpenStreetMap) хранится на сервере, сотрудникам она открывается без интернета. Скачать её нужно
один раз, интернет на сервере нужен только на это время:

```bash
sudo avers-map
```

Команда скачивает вырезку Омска из ежедневной сборки Protomaps (несколько минут, десятки мегабайт) и адреса
домов OpenStreetMap, кладёт их в `/var/lib/avers-server/map/` и ставит на карту дома Аверса, у которых совпали
улица и номер. В конце выводит дома, которые не нашлись: их главный инженер ставит на карту вручную
(руководство, раздел «Карта города»). Перезапускать сервер не нужно.

Повторный запуск обновляет карту. Дома, которые уже стоят на карте, в том числе поставленные вручную, не сдвигаются.

Если у сервера нет интернета, выполните на любом компьютере с Linux и интернетом шаги 1–3 из
`/usr/local/bin/avers-map` и перенесите `city.pmtiles` и `addresses.json` в `/var/lib/avers-server/map/`,
затем на сервере:
`sudo -u avers env $(sudo grep ConnectionStrings /etc/avers-server.env) /opt/avers-server/Avers.Server map-import /var/lib/avers-server/map/addresses.json`.

Из интернета (`avers-internet`) карта видна тем же, кому видна страница механиков.

## 4. Копии базы

Каждую ночь в 01:30 таймер `avers-backup.timer` копирует базу в `/var/backups/avers`: файл `avers-<дата>.dump`
(база вместе со сканами документов) и `avers-<дата>-files.tar.gz` (ключи входов сервера и центр сертификации Caddy).
Если сервер ночью был выключен, копия делается сразу после включения. Копии хранятся 30 дней.

Настройки — в файле `/etc/avers-backup.env` (`sudo nano /etc/avers-backup.env`):

| Настройка | Что задаёт |
|---|---|
| `AVERS_BACKUP_DAYS` | Сколько дней хранить копии на сервере (по умолчанию 30) |
| `AVERS_BACKUP_REMOTE` | Куда каждую ночь переносить копии на другой компьютер |
| `AVERS_BACKUP_KEY` | Ключ SSH для переноса (по умолчанию `/root/.ssh/avers-backup`) |
| `AVERS_RESTORE_TOLERANCE` | Допуск недельной проверки, в процентах (по умолчанию 2) |

Сделать копию сейчас: `sudo avers-backup`. Последние сообщения: `sudo journalctl -u avers-backup -n 20`.

### Сколько места нужно копиям

После первой ночи посмотрите размер копии: `ls -lh /var/backups/avers`. Под копии нужно примерно
(размер одной копии) × (`AVERS_BACKUP_DAYS` + 2): ночные копии плюс копии перед обновлениями. Сканы договоров
хранятся в базе, поэтому копия растёт вместе с ними. Свободное место: `df -h /var/backups`.

### Копии на другом компьютере

Если сломается сам сервер, копия на нём не поможет, поэтому копии каждую ночь переносятся на другой компьютер
с Linux (ниже `192.168.1.11` — его адрес). Копии принимает отдельный пользователь `avers-backup`, который может
только складывать файлы в одну папку: если сервер Аверса когда-нибудь взломают, на другой компьютер с него не попасть.
Пока перенос не настроен, в журнал копий каждую ночь пишется предупреждение.

На другом компьютере один раз:

```
sudo apt install openssh-server rsync
sudo adduser --disabled-password --gecos "" avers-backup
sudo -u avers-backup mkdir -m 700 /home/avers-backup/avers-backups /home/avers-backup/.ssh
```

На сервере Аверса создайте ключ и выведите его на экран:

```
sudo ssh-keygen -t ed25519 -N "" -f /root/.ssh/avers-backup
sudo cat /root/.ssh/avers-backup.pub
```

Снова на другом компьютере: вместо `КЛЮЧ` вставьте всю строку, которую вывела последняя команда.

```
echo 'command="/usr/bin/rrsync -wo /home/avers-backup/avers-backups",restrict КЛЮЧ' | sudo -u avers-backup tee /home/avers-backup/.ssh/authorized_keys
sudo chmod 600 /home/avers-backup/.ssh/authorized_keys
```

На сервере Аверса один раз подключитесь вручную (на вопрос о подлинности компьютера ответьте `yes`):

```
sudo ssh -i /root/.ssh/avers-backup avers-backup@192.168.1.11
```

затем в `/etc/avers-backup.env` впишите (уберите `#` в начале строк):

```
AVERS_BACKUP_REMOTE=avers-backup@192.168.1.11:./
AVERS_BACKUP_KEY=/root/.ssh/avers-backup
```

и проверьте: `sudo avers-backup` должен закончиться строкой «Копии перенесены на …». Если другой компьютер
был выключен, пропущенные копии уйдут в следующую ночь. Старые копии там сами не удаляются; раз в несколько
месяцев удаляйте лишние (`sudo rm`). В копиях все данные абонентов: доступ к этому компьютеру — только
у администратора.

Если раньше перенос был настроен строкой в `sudo crontab -e`, удалите её: теперь копии переносит сам `avers-backup`.

### Проверка восстановления

Раз в неделю (в воскресенье в 03:00) таймер `avers-restore-check.timer` восстанавливает последнюю ночную копию
во временную базу, сравнивает число строк основных таблиц с рабочей базой и удаляет временную базу.
Если копия негодная, служба видна в `systemctl --failed`, причина — `sudo journalctl -u avers-restore-check`.
Проверить вручную: `sudo avers-restore-check`.

### Восстановить из копии

Все сотрудники должны выйти из Аверса.

```
sudo systemctl stop avers-server
sudo -u postgres pg_restore --clean --if-exists -d avers /var/backups/avers/avers-2026-10-19.dump
sudo systemctl start avers-server
```

**Сервер «с нуля»** (старый сломался): поставьте Ubuntu с тем же IP-адресом и выполните `sudo bash install.sh`
(шаги раздела 2, пароль администратора можно пропустить). Затем перенесите с другого компьютера обе копии
за нужный день в `/var/backups/avers` и выполните:

```
sudo systemctl stop avers-server caddy
sudo -u postgres pg_restore --clean --if-exists -d avers /var/backups/avers/avers-2026-10-19.dump
sudo tar -C / -xzf /var/backups/avers/avers-2026-10-19-files.tar.gz
sudo chown -R avers:avers /var/lib/avers-server/keys
sudo chown -R caddy:caddy /var/lib/caddy/.local/share/caddy
sudo systemctl start caddy avers-server
```

Так восстанавливается и прежний центр сертификации: сертификат на рабочих местах переставлять не нужно,
и сотрудники остаются в своих сеансах.

## 5. Если что-то не так

| Признак | Что сделать |
|---|---|
| «Нет связи с сервером» в программе | `sudo systemctl status avers-server caddy`; в `avers.json` адрес с `https://` и без `:5115` |
| Ошибка сертификата или «соединение не защищено» | На рабочем месте не установлен корневой сертификат (раздел 3), или адрес не из списка `AVERS_ADDRESSES` |
| Служба не запускается | `sudo journalctl -u avers-server -n 50` — последние сообщения сервера; Caddy — `sudo journalctl -u caddy -n 50` |
| Сотрудник забыл пароль | Администратор задаёт новый в «Правах доступа»; если забыл сам администратор — `sudo avers-password admin` |
| «Не задан адрес сервера Аверса» | Нет файла `avers.json` рядом с программой или в нём ошибка |
| Обновление пишет «Копия не получилась» | Место на диске (`df -h /var/backups`) и `sudo journalctl -u postgresql -n 50` |

## Чего пока нет

- База пустая до переноса данных из старой базы (JACK), это отдельный шаг ([04](04-db-migration-plan.md)).
- Отключение и смена роли действуют сразу: отключённому сотруднику программа на первом же действии предлагает войти заново. Кнопки по новой роли появятся после следующего входа.
