# 09. Сервер Аверса и общая база

Чтобы все сотрудники работали в одной базе, в офисе нужен один всегда включённый компьютер с Linux.
На нём работают сервер Аверса и база PostgreSQL, а программы сотрудников подключаются к нему по локальной сети.
Это может быть тот же сервер, что и для Windows 7 ([08](08-terminal-server.md)). Интернет не нужен.

## 1. Что нужно

| Что | Какое |
|---|---|
| Сервер | **Ubuntu Server 24.04 LTS**, можно тот же, что для xrdp |
| Память | +1 ГБ к тому, что уже нужно серверу |
| Диск | +10 ГБ под базу и ночные копии |
| Сеть | Порт **5115** доступен с компьютеров сотрудников |

## 2. Установка

1. Скачайте сборку: GitHub → **Actions** → последний зелёный запуск **CI** → внизу **Artifacts** →
   **Avers-server-linux-x64**. Перенесите архив на сервер и распакуйте (`unzip Avers-server-linux-x64.zip -d avers-server`).
2. В распакованной папке выполните:
   ```
   sudo bash install.sh
   ```
   Скрипт ставит PostgreSQL, создаёт базу `avers` со случайным паролем, кладёт сервер в `/opt/avers-server`
   и запускает его как службу `avers-server`: она поднимается сама после перезагрузки.
   В конце скрипт пишет адрес, например `http://192.168.1.10:5115`.
3. Смените пароли. В новой базе заведены учебные пользователи (`admin`, `orlov`, `orlova`, `sokolova`,
   `engineer`, `lawyer`, `novikov`) с паролем `avers` и учебные абоненты. Каждому, кто будет работать:
   ```
   sudo avers-password orlov
   ```
   Пароль — не короче 6 символов. Остальным тоже смените пароль, чтобы под ними никто не вошёл.

Обновление: распакуйте новую сборку и снова выполните `sudo bash install.sh`. База и пароли сохраняются,
таблицы сервер обновит сам при запуске.

## 3. Подключить программы

Создайте файл `avers.json` с адресом из шага 2:

```
{ "server": "http://192.168.1.10:5115" }
```

- **Сервер xrdp (Windows 7):** файл `/opt/avers/avers.json`.
- **Компьютер с Windows 10:** рядом с `Avers.exe`.

На экране входа внизу должно быть написано «сервер 192.168.1.10:5115». Сотрудник вводит свой логин и пароль.

## 4. Копии базы

Каждую ночь база копируется в `/var/backups/avers` (файл на каждый день, хранятся 30 дней).
Время от времени переносите свежую копию на другой компьютер или диск: если сломается сам сервер,
копия на нём не поможет.

Восстановить из копии (все сотрудники должны выйти из Аверса):

```
sudo systemctl stop avers-server
sudo -u postgres pg_restore --clean --if-exists -d avers /var/backups/avers/avers-2026-10-19.dump
sudo systemctl start avers-server
```

## 5. Если что-то не так

| Признак | Что сделать |
|---|---|
| «Нет связи с сервером» в программе | Проверьте `sudo systemctl status avers-server` и что порт 5115 не закрыт сетевым экраном |
| Служба не запускается | `sudo journalctl -u avers-server -n 50` — последние сообщения сервера |
| Сотрудник забыл пароль | `sudo avers-password <логин>` |
| На входе написано «учебная база на этом компьютере» | Нет файла `avers.json` или в нём ошибка |

## Чего пока нет

- Данные учебные. Настоящие данные из старой базы (JACK) перенесём отдельным шагом ([04](04-db-migration-plan.md)).
- Связь программы с сервером не шифруется. Внутри локальной сети предприятия это допустимо; выпускать сервер в интернет нельзя.
- Новых сотрудников пока заводит разработчик, окна управления пользователями ещё нет.
