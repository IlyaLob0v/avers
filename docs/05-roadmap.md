- [x] Схема PostgreSQL, EF Core, сервер ASP.NET Core, вход и роли (NFR-02)
- [x] Оболочка работает через API сервера (`ServerStore`), учебная база — SQLite (`LocalStore`)
- [x] Абоненты, оплаты и долги грузятся частями, а не снимком
- [x] Журнал изменений и журнал доступа (NFR-02, NFR-07)
- [x] Проверка версии рабочего места: старой программе — «Обновите программу» (`DesktopClient.Version`, ответ 426)
- [ ] Пробная миграция справочников, абонентов, платежей; автоматическая сверка. Есть скрипты выгрузки JACK (`db/legacy`)
  и сверки (`db/migration/reconcile`), загрузки в базу Аверса нет (NFR-04 частично; Q-09, Q-28)
- [ ] Модель начислений и платежей: `Accrual` + `Payment`, много платежей на месяц, отмена пометкой, знаковое сальдо,
  справочник источников `PaymentSource`, миграция EF и подъём `DesktopClient.Version` (ADR-0010; REQ-ADS-04, REQ-CALC-07, -08)
- [ ] Одновременная правка: столбец `Version` на паспорте дома, договоре и карточке абонента, судебном деле, заявке,
  обслуживающей организации; при конфликте — 409 «Запись изменил другой сотрудник»; тест на каждую сущность (ADR-0011)
- [ ] По сети — только DTO из `Avers.Contracts`: первыми снимок, должники, отчёт для 1С; тесты формы JSON (ADR-0014)
- [x] Заявки — запросами по фильтру, сводка на сервере, заявки убраны из снимка; индексы по дате, дому, абоненту (ADR-0015)
- [ ] HTTPS в офисе (ADR-0012, NFR-07):
  - [ ] Kestrel только на `127.0.0.1:5115`, порт 5115 в `ufw` закрыт, офис — через Caddy с `tls internal`
  - [ ] Корневой сертификат Caddy на рабочие места Windows 10/11 и на терминальный сервер; шаг в `docs/09-server.md` и `deploy/xrdp`
  - [ ] Desktop без адреса сервера не открывает учебную базу, а просит адрес; учебные данные — только с ключом `--demo`
  - [x] Установщик не включает `SeedDemo`; первый администратор заводится командой на сервере
  - [x] Вход из интернета — только роль Читатель (по заголовку от Caddy)
- [ ] Резервные копии (ADR-0013, NFR-06):
  - [x] Ночной `pg_dump`, хранение 30 дней
  - [ ] Срок хранения параметром `AVERS_BACKUP_DAYS`; копия перед обновлением сервера (без неё обновление не идёт)
  - [ ] Копия на другой компьютер (`AVERS_BACKUP_REMOTE`), пока не задано — предупреждение каждую ночь
  - [ ] Раз в неделю — восстановление в `avers_restore_check` и сверка числа строк; неудача видна в `systemctl --failed`
  - [ ] В копию — ключи токенов (`/var/lib/avers-server/keys`) и данные Caddy; порядок восстановления «с нуля» в `docs/09-server.md`
