# ADR-0005. Подход к миграции данных

- Статус: Предложено
- Дата: 2026-10-14

## Контекст
Источник — Oracle 10.2, схема JACK, кириллица cp1251. Современные драйверы (ODP.NET 23, ojdbc 23) с 10.2 не работают
(требуют сервер новее) — это нужно проверить на месте, но рассчитывать на прямое подключение .NET к 10.2 нельзя.
DDL и PL/SQL не выгружены. Ошибка в деньгах недопустима.

## Варианты
1. Прямой перенос «таблица в таблицу» средствами приложения — нет современного драйвера, нет сверки.
2. **Выгрузка JACK (expdp / exp) → восстановление в Oracle Free 23 на стенде → Ora2Pg в промежуточную схему
   PostgreSQL `legacy` → SQL-преобразование в новую модель → автоматическая сверка.** Старая база не нагружается и не трогается,
   на стенде работают современные инструменты.
3. Ora2Pg прямо с боевого 10.2 через Instant Client 11.2/12.1 — допустимо как запасной путь, только чтение.

## Решение
Вариант 2, запасной — 3. Перенос повторяемый (скриптами), прогоняется многократно; финальный — при переключении.
Период параллельной работы со старым Аверсом, сверка каждую ночь.
