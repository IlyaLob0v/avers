# ADR-0002. Целевая СУБД — PostgreSQL

- Статус: Предложено (нужно подтверждение: какие лицензии СУБД есть у предприятия)
- Дата: 2026-10-14

## Контекст
Сейчас Oracle 10.2 (схема JACK), без поддержки много лет. README оболочки предполагает MS SQL Server без обоснования.
У предприятия уже работает PostgreSQL (база `abonent` модуля SMS). Пользователь сообщил, что лицензии и сервер есть,
но не уточнил, на какую СУБД. Небольшая ИТ-команда, бюджет ограничен.

## Варианты
1. **PostgreSQL 18** — бесплатно, без лимитов по ядрам и объёму, уже есть на предприятии, зрелый провайдер Npgsql для EF Core,
   сильный инструмент миграции с Oracle (Ora2Pg), похожие на Oracle возможности (последовательности, PL/pgSQL, CTE, оконные функции).
   Минус — нужен администратор, который знает PostgreSQL (на предприятии он, судя по SMS, есть).
2. **MS SQL Server** — хорошо с .NET, если лицензии уже куплены. Минусы: стоимость лицензий на ядро, Express ограничен 10 ГБ
   на базу и 1 сокетом/4 ядрами, Ora2Pg не подходит (нужен SSMA).
3. **Новый Oracle (19c/23ai)** — минимум переделки SQL, но лицензии Oracle дороги; Oracle Free ограничен 12 ГБ данных.
4. **Остаться на Oracle 10.2** — нет поддержки, нет современных драйверов .NET. Отклонено.

## Решение
Предлагаем PostgreSQL 18. Если у предприятия уже есть лицензии MS SQL Server Standard и администратор под него,
решение пересматриваем — архитектура (EF Core) позволяет сменить провайдера до начала миграции данных.

## Последствия
- Схема пишется под PostgreSQL (snake_case, `bigint identity`, `numeric(12,2)` для денег, `citext`/`pg_trgm` для поиска по ФИО).
- Миграция — через Ora2Pg (ADR-0005).
- Нужен регламент резервного копирования PostgreSQL.
