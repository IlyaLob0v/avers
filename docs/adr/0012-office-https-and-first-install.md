# ADR-0012. HTTPS в офисе и первичная установка сервера

- Статус: Принято
- Дата: 2026-11-06
- Участники: Илья, архитектор

## Контекст
Kestrel слушает `http://0.0.0.0:5115`, порт открыт в `ufw` (`deploy/server/install.sh`): в сети 192.168.37.0/24
логин, пароль, токен на 12 часов и персональные данные абонентов идут открытым текстом — противоречит NFR-07 (152-ФЗ).
HTTPS есть только наружу: Caddy публикует `/m/` с сертификатом Let's Encrypt (`avers-internet`). Кроме того,
установка раньше включала `SeedDemo=true` — на боевом сервере появлялись учебные данные и учётки с известным паролем.
Desktop без адреса сервера молча открывает учебную SQLite, и сотрудник может вести учёт «не в той базе».

## Варианты
1. **HTTP внутри доверенной сети.** Ничего не делать. Отклонено: пароли, токен и ПДн в открытом виде; сеть общая
   (Wi-Fi, гости, сервер 1С), NFR-07 требует шифрование канала.
2. **Самоподписанный сертификат Kestrel, отпечаток закреплён в `avers.json` Desktop.** Без лишних служб.
   Минусы: своя проверка сертификата в `HttpClient`; смена сертификата = правка `avers.json` на каждом месте;
   браузер (страница `/m/` в офисе, проверка `/health`) ругается.
3. **Caddy с `tls internal` для офисного адреса.** Caddy уже стоит; свой центр сертификации (корневой на 10 лет,
   рабочие сертификаты выпускает и продлевает сам). Нужно один раз поставить корневой сертификат на рабочие места.

## Решение
Вариант 3.
- Kestrel слушает только `127.0.0.1:5115`, порт 5115 в `ufw` закрыт; офис и интернет идут через Caddy (443).
- Офисный сайт Caddy — `tls internal`. Корневой сертификат (`/var/lib/caddy/.local/share/caddy/pki/authorities/local/root.crt`)
  ставится на Windows 10/11 командой `certutil -addstore -f Root root.crt` (от администратора, можно групповым
  скриптом) и на терминальный сервер Linux (`/usr/local/share/ca-certificates/` + `update-ca-certificates`).
  Машины Windows 7/8 ничего не ставят — Аверс у них работает на терминальном сервере (ADR-0008).
- Первый администратор заводится командой на сервере (логин; пароль вводится, в истории команд не остаётся).
  Учебные данные: только в среде Development и в Desktop с ключом `--demo`. Установщик `SeedDemo` не включает.
- Desktop без адреса сервера учебную базу не открывает, а просит адрес.
- Вход с внешнего адреса (через интернет-сайт Caddy) — только роль «Читатель», даже если у учётки роли шире.
  Признак «внешний» сервер берёт из заголовка, который ставит (и перезаписывает) интернет-сайт Caddy, а не из адреса клиента.

## Последствия
- Адрес сервера в Desktop — `https://<имя или IP>/`; в инструкциях (`docs/09-server.md`, `deploy/xrdp`) — шаг установки корневого сертификата.
- Закрытый ключ центра сертификации Caddy остаётся на сервере и должен попадать в резервную копию (ADR-0013);
  потеряли ключ — новый корневой сертификат придётся раздать на все места заново.
- В `avers-internet` проверка входа учёткой с паролем `avers` больше не годится — нет учебных учёток на боевом сервере.
- Тесты: учебные данные не создаются вне Development; внешний вход с ролью Кассир получает только права Читателя.
