# ADR-0018. Загрузка исторических данных по запросу

- Статус: принято
- Дата: 19.11.2026

## Причина

История JACK содержит миллионы операций. Открытие дома загружало историю всех его квартир,
а фильтры должников работали по полному списку на рабочем месте. Небольшая учебная база скрывала эти затраты.

## Решение

- Запрос дома возвращает список квартир и историю одного выбранного абонента. Для смены квартиры
  клиент запрашивает её историю отдельно. Во время загрузки операции с карточкой недоступны.
- Должники отбираются в БД и выдаются страницами по 100 строк. Итоги по домам запрашиваются отдельно.
  Полный отбор загружается только по явной команде выгрузки или формирования уведомлений.
- Исходные операции JACK доступны в карточке по запросу, страницами по 100, с отбором по расчётному году.
  Исходные суммы, идентификаторы и даты не изменяются. Этот просмотр не меняет правила расчёта долга.
- Группировки месячного отчёта для 1С выполняются в БД. Для рабочих месяцев и даты поступления
  предусмотрены отдельные индексы.
- PostgreSQL хранит производные суммы по абоненту и году в `PaymentYearTotals`. Триггеры на оператор
  INSERT/UPDATE/DELETE обновляют их атомарно в транзакции исходной записи; TRUNCATE очищает итоги.
  Изменения целого пакета группируются одним оператором. Миграция заполняет итоги существующих месяцев
  под блокировкой записи, исключающей разрыв между заполнением и установкой триггеров.
- Долги прошлых лет читаются из годовых итогов, текущий год — из месяцев до текущего.
  Старший неоплаченный месяц вычисляется по исходным строкам только для выбранной страницы.
  SQLite использует прямую группировку исходных месяцев. Денежные правила обоих путей одинаковы.
- Версия протокола рабочего места — 6. Старый клиент не должен трактовать неполную историю дома как полную.
- Телефоны нормализуются до цифр одинаково в PostgreSQL и учебном режиме. Поиск подстроки использует
  `pg_trgm` по выражению нормализации; фамилии и улицы — индексы `lower(...) text_pattern_ops`.

## Приёмка переноса

Бухгалтерские запросы должны быть заполнены и совпадать с эталонами. Отсутствие запросов, ошибки, расхождения
или подозрительная кодировка блокируют рабочую приёмку. Техническая самопроверка стенда явно отключает
бухгалтерскую приёмку и не сообщает о её прохождении.

Дополнительно проверяется начисление каждой пары «абонент — месяц». Общие итоги не заменяют такую сверку.
Производные годовые суммы также сверяются с рабочими месяцами.
Раннее сальдо, деноминация, переплаты и правила обмена 1С подтверждаются на копии JACK с бухгалтерией.

## Проверка объёма

`tools/Avers.DataProbe` создаёт отдельную базу с искусственными данными, проверяет денежный эталон,
измеряет запросы и удаляет эту базу. Реальные данные и существующие базы не изменяются.
Этот прогон не подтверждает работу производственного оборудования и миграцию реальной истории.
