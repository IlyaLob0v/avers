# ADR-0015. Загрузка заявок в настольную программу

- Статус: Принято
- Дата: 2026-11-06
- Участники: Илья, архитектор

## Контекст
Абоненты, оплаты и долги уже грузятся частями (`docs/03-architecture.md`), а заявки (`WorkTicket`, в глоссарии — `Demand`)
по-прежнему приходят в снимке справочников целиком (`AversSnapshot.Load`: все заявки и все абоненты, у которых есть заявки)
и перезапрашиваются после каждой записи. История `DEMANDS` в JACK копится годами и только растёт: снимок тяжелеет,
вход и каждое сохранение замедляются. Вместе с заявками в память каждого рабочего места, в том числе общего
терминального сервера, попадают персональные данные этих абонентов. Сводка по заявкам считается на клиенте
из полного списка.

## Варианты
1. **Оставить в снимке.** Просто, но время входа и память растут с историей, ПДн всех заявок у каждого сотрудника.
2. **Снимок только открытых заявок.** Меньше данных, но архив всё равно нужен (поиск по абоненту, отчёты),
   и открытых в сезон бывает много.
3. **Заявки — запросами с фильтром, сводка — на сервере.** Тот же подход, что для абонентов и долгов.
   Минусы: экран заявок ждёт ответа сервера; нужен новый API и переделка `TicketsViewModel`.

## Решение
Вариант 3. Заявки и их абоненты из снимка убираются. Заявки по домофонам (`IntercomTickets`) — тем же способом,
когда их объём станет заметным. Desktop запрашивает их по фильтру: период (по умолчанию — текущий месяц
и все незакрытые), дом, абонент; список ограничен по числу строк, сортировка и фильтр — на сервере, права роли
(Q-17: АДС видит все, правит свои) проверяет сервер. Сводка (те же показатели, что сейчас считает клиент) — агрегат
за период, который сервер считает запросом к базе. После сохранения заявки перечитывается только она, а не снимок.

## Последствия
- Снимок становится меньше; вход не зависит от объёма истории заявок.
- В памяти клиента — только заявки открытого фильтра.
- Ответы — DTO в `Avers.Contracts` с `Version` (ADR-0011, ADR-0014); меняется форма снимка — поднять `DesktopClient.Version`.
- Учебная база (`LocalStore`) выполняет те же запросы через общий код `Avers.Data`.
- Индексы по дате, дому и абоненту в таблице заявок.
