# ADR-0011. Одновременная правка одной записи

- Статус: Принято
- Дата: 2026-11-06
- Участники: Илья, архитектор

## Контекст
Сотрудники работают с одной базой (ADR-0003). Сейчас у записей нет ни `xmin`, ни версии строки: если двое открыли
паспорт дома и сохранили по очереди, вторая правка молча затирает первую. Модель одна на две СУБД:
PostgreSQL на сервере и SQLite учебной базы Desktop (`LocalStore`), операции записи общие (`Avers.Data`).

## Варианты
1. **Последний выигрывает (как сейчас).** Ничего не делать. Минус — потеря правок без следа для сотрудника.
2. **`xmin` PostgreSQL как маркер версии** (Npgsql: `uint` + `IsRowVersion()`). Плюсы: столбец не нужен,
   меняется сам при любом `UPDATE`. Минусы: только PostgreSQL — в SQLite такого столбца нет, понадобится
   отдельная настройка модели под каждую СУБД; значение — номер транзакции, меняется и от служебных обновлений
   той же строки (пересчёт `LastPaymentDate` и т. п.), что даст ложные конфликты.
3. **Свой столбец `Version` (int).** Увеличивается операцией записи, объявлен маркером параллелизма EF
   (`IsConcurrencyToken()`). Плюсы: одинаково в PostgreSQL и SQLite, понятен в тестах, растёт только
   при правке самой карточки. Минусы: увеличивать надо явно; `ExecuteUpdate` маркер не проверяет —
   условие версии пишется в `Where` вручную.
4. **Пессимистическая блокировка на время открытия карточки.** Конфликтов нет, но зависшие блокировки
   при закрытом без выхода окне и на терминальном сервере — хуже, чем редкий конфликт.

## Решение
Вариант 3. Столбец `Version` — на редактируемых сущностях: паспорт дома, договор и карточка абонента,
судебное дело, заявка, обслуживающая организация. DTO для чтения отдаёт версию, запрос на сохранение её возвращает.
Сервер сравнивает; при несовпадении — ответ **409** с текстом «Запись изменил другой сотрудник, обновите и повторите»,
ничего не записывается. Desktop показывает текст и перечитывает карточку.
Деньги (оплата, отмена, корректировка) этим маркером не защищаются: это атомарные операции в одной транзакции
с блокировкой строки абонента (ADR-0010) — второй кассир не «перезаписывает», а добавляет свой платёж.

## Последствия
- Миграция EF: `Version` с умолчанием 1 на перечисленных таблицах; операции записи увеличивают её и проверяют.
- Тест на каждую сущность: два сохранения с одной версией — второе получает 409.
- Старое рабочее место без версии в запросе затёрло бы чужую правку — поднять `DesktopClient.Version`.
- Слияния правок нет: сотрудник повторяет ввод. Если конфликты окажутся частыми — вернуться к вопросу.
