# ADR-0014. Контракт API и обновление рабочих мест

- Статус: Принято в части контракта и версии клиента; автообновление Desktop — Предложено
- Дата: 2026-11-06
- Участники: Илья, архитектор

## Контекст
По сети ходят классы `Avers.Domain` и `Avers.Data` (`AversSnapshot`, `Debtor` со вложенным `CourtCase`,
`AccountingReport` и др.); `Avers.Contracts` покрывает только часть API. Любое переименование поля в модели базы
незаметно меняет JSON и ломает рабочие места, а в ответ попадают поля, которых клиенту не положено.
Версия клиента одна — `DesktopClient.Version`; сервер отвечает 426 «Обновите программу» старому Desktop
(`DesktopVersionCheck`). Как сотрудник после этого обновится — не решено: сборки CI раздаются вручную.
Рабочие места: Windows 10/11 — Desktop ставится на ПК; Windows 7/8 — через терминальный сервер Linux с xrdp (ADR-0008),
там одна установка на всех.

## Варианты
**Контракт.** 1) Оставить классы модели в ответах — меньше кода, но связка «таблица = JSON». 2) **Всё, что ходит по сети, —
DTO в `Avers.Contracts`**, отображение в обработчиках сервера; форма JSON закреплена тестами.

**Обновление Desktop.**
1. **Velopack** (MIT, на nuget.org на 06.11.2026 — 1.2.161). Установка в `%LocalAppData%` без прав администратора,
   дельта-обновления, замена запущенной программы и откат — готовые; источник обновлений — любые статические файлы
   по HTTP(S), в том числе папка на нашем сервере за Caddy. Минусы: на Windows — установка на каждого пользователя
   отдельно; запуск .exe из профиля может запрещаться политикой или антивирусом; без подписи кода — предупреждение SmartScreen.
   Для общего терминального сервера Linux не подходит (там обновляет администратор).
2. **Своя схема:** сервер отдаёт текущую версию и ссылку на архив, Desktop при 426 предлагает скачать и ставит из общей
   папки или с сервера. Без зависимостей, но замену файлов запущенной программы, откат и повтор при сбое
   пришлось бы писать и поддерживать самим.

## Решение
- **Контракт — вариант 2.** Новые и изменяемые ответы — только DTO из `Avers.Contracts`; существующие переводятся
  по мере правки, первыми — снимок, должники, отчёт для 1С. Тесты-снимки формы JSON ключевых ответов (снимок, абоненты дома,
  должники, отчёт для 1С, карточки с `Version` по ADR-0011): изменение формы — осознанная правка снимка в том же PR.
- **`DesktopClient.Version` поднимается**, когда старый Desktop может испортить данные: перестаёт присылать обязательное
  поле, затирает новое поле пустым, не знает о новом правиле (второй платёж, версия записи). Добавление поля в ответ
  и новый метод API версию не поднимают. Подъём отмечается в описании PR.
- **Автообновление — рекомендуем Velopack** для Windows 10/11 с источником обновлений на нашем сервере
  (`https://<сервер>/updates/`, раздаёт Caddy). Desktop проверяет обновление при запуске и при ответе 426 предлагает
  установить. Терминальный сервер Linux — без Velopack: администратор обновляет общую установку скриптом из `deploy/xrdp`
  тем же архивом CI; на Windows 7/8 ничего не ставится.

Что нужно решить, чтобы принять часть про обновление: разрешена ли установка программ в профиль пользователя
(политики, антивирус); нужна ли подпись кода и где её взять; согласен ли администратор раздавать обновления с сервера Аверса.
Если установка в профиль запрещена — вариант 2 с общей папкой и установкой администратором.

## Последствия
- Больше кода отображения на сервере; зато модель базы меняется, не трогая рабочие места.
- CI собирает пакет Velopack (`vpk pack`) рядом с архивами win-x64 и linux-x64.
- Сотрудник после 426 не остаётся без программы: обновление в один щелчок вместо ручной раздачи.
