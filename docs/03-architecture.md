# 03. Архитектура

Статус: действует, сверено с кодом 06.11.2026. Решения с обоснованием — в `docs/adr/`. Решения архитектурного ревью
06.11.2026 (ADR-0010…0016) приняты, но в коде сделаны ещё не везде — см. «Код и решения: расхождения». Что ещё
не сделано — в разделе «Дальше».

## Коротко

Модульный монолит на .NET 10 LTS: один сервер приложений (ASP.NET Core) с одной базой PostgreSQL,
к нему подключаются настольное приложение Avalonia 12 на рабочих местах Windows 10/11 и веб-интерфейс
для телефонов радиомехаников. Машины с Windows 7 и 8 работают с тем же настольным приложением через
терминальный сервер Linux с xrdp (ADR-0008). Загрузка реестров, обмен с 1С и ночные отчёты — в фоновой службе
`Avers.Worker` рядом с сервером: та же база и тот же `Avers.Data`, отдельный процесс (ADR-0016).

## Слои и проекты

```
src/
  Avers.Domain/      сущности и правила без базы: абонент, дом, оплата, долг (Billing), заявка, роли, календарь сроков
  Avers.Data/        EF Core (PostgreSQL на сервере, SQLite в учебном режиме), миграции, учебные данные
                     и операции записи с журналом изменений: оплата, договор, тарифы, заявки, ППР, словарь…
  Avers.Contracts/   DTO API, общие для сервера и Desktop
  Avers.Server/      ASP.NET Core 10, Minimal API: вход, права, обработчики по разделам, страница /m/ для телефонов
  Avers.Desktop/     Avalonia 12, MVVM (CommunityToolkit.Mvvm); печать PDF/Word и выгрузки Excel делает сам
  Avers.Worker/      будет (ADR-0016): фоновая служба, берёт задания из таблицы в базе и вызывает операции Avers.Data
tests/
  Avers.Domain.Tests/  Avers.Data.Tests/  Avers.Server.Tests/  Avers.Desktop.Tests/ (Avalonia.Headless)
```

Зависимости идут в одну сторону: `Domain` ← `Data` ← `Server`, `Worker` и `Desktop`; `Contracts` знают только сервер и Desktop.
Операция записи пишется один раз в `Avers.Data` и вызывается и обработчиком сервера, и учебной базой Desktop;
сервер добавляет к ней проверку входных данных и прав. Отдельные слои `Application` и `Infrastructure`
не заводим, пока хватает этого.

`Avers.Desktop` работает через `IAversStore`: `ServerStore` ходит в API сервера (общая база PostgreSQL),
`LocalStore` — в свою учебную SQLite, когда адрес сервера не задан. После входа и после каждой записи программа
получает снимок справочников (`GET /api/desktop/snapshot`: улицы, дома, ППР — только то, что положено роли;
сейчас в нём ещё и заявки).
Абонентов со счетами в снимке нет, они грузятся частями: абоненты дома с оплатами — при выборе дома
(`GET /api/houses/{id}/subscribers`), поиск выполняет сервер (`GET /api/subscribers`), должников и долг по домам
сервер считает по всей базе (`GET /api/debts`, при открытии юристов и отчётов), итоги месяца для 1С —
`GET /api/reports/accounting`. На тестовой базе в 45 000 абонентов и 1,6 млн оплат вход занимает около секунды
вместо 13, программа держит в памяти около 100 МБ вместо 1,1 ГБ. Заявки пока приходят в снимке целиком вместе
с их абонентами; решено (ADR-0015) убрать их из снимка и грузить запросом по фильтру (период, дом, абонент),
сводку считать на сервере — **в работе**.

Модели представления Desktop: `MainViewModel` — оболочка (вход, меню, снимок справочников, выбранные улица, дом
и квартира, карточка абонента, оплаты, печать). У остальных экранов своя модель (`TicketsViewModel`,
`ContractsViewModel`, `LegalViewModel`, `ReceiptsViewModel`, `ReportsViewModel`, `PprViewModel` и т. д.): она получает
оболочку в конструкторе, а в разметке общее берёт через `Shell.*`. Новый экран делается так же.

## Сквозные вопросы

- **Вход.** Учётные записи в таблице пользователей Аверса, пароли — PBKDF2-SHA512. Сервер выдаёт токен на 12 часов
  (ASP.NET Core BearerToken); ключи подписи хранятся в `/var/lib/avers-server/keys`, поэтому вход переживает
  перезапуск сервера. На каждом запросе пользователь перечитывается из базы: отключённый теряет доступ сразу.
  Попытки входа ограничены: 10 в минуту с адреса из интернета, 60 — в офисе (xrdp: все сотрудники с одного адреса). Сотрудников заводит администратор на экране «Права доступа».
- **Права.** Роли и модули — `RoleCatalog` (Domain), политики сервера — `Avers.Server/Auth/Permissions.cs`.
  Проверка на сервере в каждом обработчике; клиент лишь скрывает кнопки.
- **Журнал изменений.** Таблица журнала (`ChangeLog`): кто, когда, что было и стало. Запись идёт в той же транзакции,
  что и само изменение; править журнал нельзя. Смотрит администратор. Фоновая служба пишет от имени
  «Фоновая служба (задание № …, поставил: …)», отдельной учётной записи у неё нет (ADR-0016).
- **Начисления и платежи (ADR-0010).** Начисление (`Accrual`, одно на абонента и месяц) и платёж (`Payment`, сколько угодно
  на месяц, с источником из справочника `PaymentSource`) — разные записи. Отмена — пометка, отменённый платёж виден,
  но не считается. Сальдо знаковое: долг и аванс. Второй платёж за оплаченный месяц — только с подтверждением кассира.
- **Одновременная правка (ADR-0011).** Карточки (паспорт дома, абонент и договор, судебное дело, заявка, организация)
  несут столбец `Version`; сохранение со старой версией — ответ 409 «Запись изменил другой сотрудник, обновите
  и повторите». Деньги версией не защищаются: внесение и отмена — одна транзакция с блокировкой строки абонента;
  так же пишет и фоновая служба, порциями, чтобы не держать кассу (ADR-0016).
- **Контракт API и версия клиента (ADR-0014).** По сети — только DTO из `Avers.Contracts`, форма ключевых ответов закреплена
  тестами. `DesktopClient.Version` поднимается, когда старый Desktop может испортить данные; сервер отвечает ему 426
  «Обновите программу». Автообновление (Velopack) — предложено.
- **Файлы.** Схемы СКПТ и сканы договоров хранятся в PostgreSQL (ADR-0009) и попадают в ночную копию базы.
  Телефону схема показывается с водяным знаком. Сейчас знак рисует страница `/m/` на холсте, а `/api/mobile/schemes/{id}`
  отдаёт картинку без него; знак на стороне сервера сделан в ветке `fix/permissions`, она ещё не влита.
- **Печать и отчёты.** Делает Desktop на месте: PDF (SkiaSharp), Word (Open XML), Excel (ClosedXML, ADR-0007).
  Данные для них сервер считает по всей базе (`/api/debts`, `/api/reports/accounting`).
- **Обмен с 1С.** Пока файл Excel за месяц (кнопка «Для 1С»); прямая загрузка по OData — позже (ADR-0006),
  её будет делать фоновая служба (ADR-0016).
- **Фоновые задачи (ADR-0016).** Загрузка реестров и файла ОЭК, обмен с 1С, ночные отчёты — служба `Avers.Worker`.
  Сервер проверяет права и ставит задание в таблицу в базе, служба забирает его (`FOR UPDATE SKIP LOCKED`; способ передачи заданий — предложено),
  Desktop спрашивает состояние. HTTP-порта у службы нет, схему базы меняет только сервер. В учебном режиме службы нет:
  `LocalStore` вызывает те же операции `Avers.Data` напрямую.
- **Развёртывание.** Сервер — Ubuntu Server: `deploy/server/install.sh` ставит PostgreSQL, службу systemd `avers-server`
  (`docs/09-server.md`); рядом — служба `avers-worker` из того же архива (ADR-0016). Решено (ADR-0012): Kestrel слушает
  только `127.0.0.1:5115`, порт 5115 закрыт; офис и интернет идут через Caddy на 443. В офисе — HTTPS с `tls internal`
  (корневой сертификат Caddy ставится на рабочие места и терминальный сервер), из интернета — только страница `/m/`
  с Let's Encrypt (`avers-internet`), вход оттуда — только с правами Читателя. Первый администратор заводится командой
  `avers-password`, учебных данных на сервере нет. Desktop — самодостаточные сборки win-x64 и linux-x64 из CI;
  Windows 7 и 8 — через xrdp (`deploy/xrdp`), запасной вариант на Windows Server — `deploy/rds`.
- **Резервные копии (ADR-0013).** Ночной `pg_dump --format=custom` (срок хранения — `AVERS_BACKUP_DAYS`), копия перед
  обновлением, каждая копия — на другой компьютер (`AVERS_BACKUP_REMOTE`), раз в неделю — пробное восстановление
  во временную базу и сверка числа строк. В копию входят ключи подписи токенов и данные Caddy. Журнал WAL — после Q-27.
- **Тесты и CI.** xUnit; серверные тесты идут на SQLite, а в CI ещё и на настоящем PostgreSQL (`AVERS_TEST_POSTGRES`).
  CI собирает, гоняет тесты, проверяет `dotnet format` и пробный запуск программы.
